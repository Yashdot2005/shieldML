ShieldML Model Card & Governance Specification

MLOps Standard v1.0

1. Model Overview

ShieldML is an ensemble machine learning system engineered for real-time transactional fraud detection. It integrates Random Forest, XGBoost, and LightGBM classifiers using calibrated soft-voting probability aggregation, optimized for an asymmetric F2 loss function that weights fraudulent transaction recall higher than false alarms.

2. Intended Use & Serving Constraints

  • Primary Intended Use: Real-time authorization gate for card-not-present (CNP) and card-present (CP) financial transactions.
  • Latency SLA: Sub-50ms 95th percentile response latency for single-transaction requests.
  • Out of Scope: Batch account credit scoring or anti-money laundering (AML) multi-hop network analysis.

3. Class Imbalance & Mitigation Strategy

Financial transaction fraud is characterized by extreme class imbalance (~1.2% fraud). ShieldML mitigates this using SMOTE oversampling applied strictly to the training partition, supplemented by cost-sensitive tree loss scaling (scale_pos_weight). Validation and held-out test sets remain pristine and un-sampled to ensure unbiased evaluation.

4. Known Limitations & Bias Considerations

  • Cold Start Accounts: Newly provisioned cards without historical velocity rely primarily on merchant amount z-scores and categorical risk factors until behavioral history accumulates.
  • Concept Drift: Novel fraud vectors (e.g., emergence of previously unseen merchant categories) require recurring weekly model retraining and MLflow champion-challenger promotion.
  • Cross-Border Geographic Bias: Higher baseline risk weight on non-domestic transactions must be balanced with user travel exemption mechanisms.
